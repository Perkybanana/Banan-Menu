# Banan Menu 1.0.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the user-approved 1.0.0 improvements, independent checkpoint selection and a public, downloadable mod repository.

**Architecture:** Keep the existing game-thread action queue and snapshot UI. Separate portable validation logic from game adapters. Preserve verified 0.4.16 while testing the new candidate.

**Tech Stack:** C++20, MSVC, Win32, UE reflection, ImGui, CMake/CTest.

**Spec:** ../specs/2026-10-24-banan-100-design.md

## Global Constraints

- All game mutations run on the game thread; the render thread consumes copied snapshots.
- Keep RU/EN UI strings in lang.cpp. Do not enable new cheats automatically.
- Preserve the native chapter selector and return-to-main-menu fix.
- Preserve upstream MIT and dependency notices.
- Do not publish user saves, logs, memory dumps, personal paths, credentials or proprietary game binaries/assets.
- Release number is 1.0.0; a development build is not a verified stable release.

## Review Focus

- Missing or stale UObject instances after chapter transitions must disable actions without crashing.
- Multi-stack counts and capacity failures must not falsely report success or spill resources.
- Loading checkpoint data must not overwrite any existing user playthrough.
- Malformed profile/pack files must not cause unbounded allocation, path traversal or unsafe native calls.
- Unavailable or untested engine commands must not be presented as working features.

## Task 1: Exact crafting material totals

**Files:** src/resources_core.h, src/features.h, src/features.cpp, src/menu.cpp, src/lang.cpp, tests/resources_test.cpp, CMakeLists.txt.
**Interfaces:** Snapshot carries six observed material totals; `feat::SetResourceTotal(int materialIndex, int total)` queues an action. Portable reconciliation accepts read/add/remove callbacks and returns observed before/after and a status.

- [ ] Write and run failing behavioral tests for increasing/decreasing totals, multi-stack removal, idempotence, out-of-range input, failed reads, no-progress mutations, capacity-limited addition and intermediate failures.
- [ ] Implement a bounded, observed-count reconciliation algorithm; game adapter uses ItemManager calls and checks actual count changes.
- [ ] Add six RU/EN inventory rows with current total, editable target and an explicit Set button; targets 0..9999, carried inventory only.
- [ ] Build and run relevant CTest checks. Review the change before the next implementation task.

## Task 2: Complete checkpoint research and independent state library

**Files:** src/checkpoints_core.h, src/checkpoints.cpp, src/checkpoints.h, src/missions.cpp, src/menu.cpp, src/lang.cpp, tests/checkpoints_test.cpp; local tooling outside published source.
**Interfaces:** a copied `checkpoints::Snapshot` with pack entries and load readiness; queued load operation accepts an immutable entry ID, never a raw caller-controlled path.

- [ ] Inspect the remaining demo/start-state mechanism and actual save path resolution. Document what it can initialize; do not assume arbitrary checkpoints work.
- [ ] Define and test strict pack entry validation and loading state transitions before writing the runtime adapter.
- [ ] Implement isolated loading and authoring without reading player saves as the template source.
- [ ] Produce independent state data and verify reload, control and next story step for each admitted entry. Entries without this proof remain unavailable.
- [ ] Verify chapter list and return-to-menu behavior with the new selector.

## Task 3: Profiles, favorites and equipment presets

**Files:** src/presets_core.h, src/presets.cpp, src/presets.h, src/menu.cpp, src/features.cpp, src/lang.cpp, tests/presets_test.cpp.
**Interfaces:** profiles contain only declared toggles/values; equipment entries contain item IDs and positive bounded quantities; actions use the existing game queue.

- [ ] Test invalid/nonnumeric/nonfinite values, schema mismatch, unknown item IDs and Unicode profile names.
- [ ] Implement named presets, favorites and explicit equipment application; no one-shot actions during profile loading.
- [ ] Validate persistence across restart and map changes.

## Task 4: Verified weapon, camera and developer-command improvements

**Files:** focused feature modules, src/menu.cpp, src/lang.cpp, tests for reversible override state.
**Interfaces:** reflected field capability checks, map-associated camera bookmarks, allowlisted developer commands.

- [ ] Inspect native weapon fields and command implementations; choose only supported controls.
- [ ] Test restoring original values after disabling, weapon switch and object destruction.
- [ ] Implement supported weapon controls, camera bookmarks/visibility and enemy spawning entry points.
- [ ] Verify each function in game. Record unusual item candidates separately until equip/attack/save-load checks pass.
