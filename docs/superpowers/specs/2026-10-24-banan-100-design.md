# Banan Menu 1.0.0

The user approved the proposed menu improvements, requested version 1.0.0, and explicitly requested a public GitHub repository with downloadable releases. They delegated implementation decisions ("do as you can"); no further design gate is required. On 2026-10-25 the user explicitly canceled arbitrary checkpoint starts and the independent prepared-state library. Preserve episode selection; checkpoint loading is no longer a release requirement.

## Scope and order

1. Preserve the existing native chapter selector and its return-to-main-menu fix. Do not implement or package arbitrary checkpoint starts or a prepared-state library; this work was canceled on 2026-10-25.
2. Exact totals for the six crafting materials; settings profiles; item favorites and equipment presets.
3. Camera bookmarks are implemented and user-tested. Enemy spawning and named unusual-weapon/power research were completed within the user's narrowed scope, with acceptance limits recorded below. Recoil, attack-speed and hand/weapon-visibility controls are excluded from this task. Filename presence is not evidence of cut content; do not expose experimental items as restored content without verification.
4. Publish source, installation instructions and tested downloadable builds under Perkybanana. Preserve upstream MIT and dependency notices. Do not publish user saves, logs, memory dumps, personal paths, credentials or proprietary game binaries/assets.

The user also explicitly approved adapting an unusual or enemy weapon for player use if feasible. Check the actual player equipment, animations and damage path first. An enemy actor or a quest object is not automatically a usable player weapon; a mesh replacement alone must not be described as restored combat functionality.

## Implementation choices

Keep C++20, MSVC and the existing reflective Unreal adapter and ImGui overlay. All game mutations run on the game thread; the render thread consumes copied snapshots. Keep RU/EN UI strings in lang.cpp. Do not enable new cheats automatically. Missing native functionality disables an action with a meaningful reason. Settings and user saves must survive updates.

Checkpoint-start research ended without an installed loader or distributed state library. The user withdrew this feature on 2026-10-25. Do not resume its implementation, state authoring or game inspection unless the user requests it again. Existing chapter selection is the requested way to start from another episode.

Exact material totals apply to the carried inventory, not stash. Show observed totals, accept integers 0..9999 and report if inventory capacity prevents reaching a target. Increasing must not intentionally drop overflow at the player's feet. Decreasing must safely handle multiple stacks. Repeat actions are idempotent; stale counts must be reread on the game thread. Only the six named materials are affected.

Profiles store switches and numeric settings only, never actions such as achievements, objective completion, spawning or loading saves. Equipment presets and experimental tools require explicit button presses. Photo bookmarks stay associated with their map. The dev.3 native enemy-spawner panel failed runtime acceptance: it opens with an empty list because it needs a configured editor helper. The dev.4 direct actor-construction replacement also failed: created enemies were invisible and inert, and Genesis finishing after Kill nearby crashed with a missing skinned asset. Use the full reflected EnemyManager MakeSpawnInfo/SpawnThreat initialization path for the compact World spawner, preserving engine-constructed defaults and native value lifetimes. Keep the five class references found in the helper defaults and bound each explicit request to 1..5 actors; class loading happens only after the click. Report usable readiness only after native initialization and a valid model are observed; dispatch or actor existence alone is insufficient. Skip incomplete enemies in Kill nearby. Actual combat and finishing behavior remain separate runtime acceptance checks.

## Release acceptance

Build and relevant tests pass, fresh code review completes, and game checks are recorded with their actual scope. Keep the installed candidate until a reviewed replacement is ready and the game is closed. Do not publish an untested 1.0.0 stable release. Source development may be public with its status explicit. Canceled checkpoint starts are not a remaining release gate. The user accepted dev.2 camera Save/move/rotate/Restore on Chapter5 and, separately, retention of the bookmark with Restore disabled after switching chapters, without a crash. This does not establish all-slot, all-FOV or death/reload coverage. User accepted dev.8 ordinary/exploding Hellghoul behavior, then dev.9 fresh-Cambion normal depletion/Genesis and the separate Kill nearby/finisher check. Count 5, concurrent boss HUDs, all five combat paths and every map remain unexhausted. Named residual-content research closed with no demonstrated ready-to-enable additional weapon/power; conditional adaptation did not justify speculative implementation. Final stable source/package review, scan/checksums, publication and settings-preserving installation remain release gates.
