# Banan Menu для Hellraiser: Revival

**1.0.0-dev.2 — сборка в разработке для Windows-версии игры в Steam, а не проверенный стабильный релиз 1.0.0.** Поддерживается штатный выбор эпизода/главы; начало с произвольной контрольной точки не входит в текущий объём работ. Пользователь сообщил, что закладки камеры недоступны в dev.1. Выявленная ошибка разрешения сильной ссылки свойства исправлена в исходниках и покрыта автономными тестами; приёмка dev.2 в игре ещё не выполнена.

[English](README.md) · [Изменения](CHANGELOG.md) · [Область проверки](docs/VERIFICATION.md)

## Что есть в исходниках

- Игрок и бой: здоровье, урон, боеприпасы, прочность, прицеливание и способности Genesis Configuration.
- Движение и мир: полёт/noclip, скорость/прыжок, сохранённые позиции, телепортация к загруженным контрольным точкам уровня, скорость времени, управление ИИ, свободная камера, FOV и скрытие HUD.
- ESP для врагов, предметов, контейнеров и точек сохранения.
- Инвентарь: деньги, точные количества шести переносимых материалов (0..9999), каталог предметов, избранное, явные наборы выдаваемых предметов и локальные профили настроек.
- Текущие цели, уровень магазина и достижения Steam; штатный выбор глав сохранён. Можно настроить язык, масштаб и клавиши.
- Три защищённые закладки свободной камеры в пределах текущего сеанса. Их работа в игре ещё требует приёмки.

Доступность зависит от игрока, карты и поддерживаемых штатных интерфейсов игры. Наборы запрашивают выдачу предметов и подчиняются существующему поведению вместимости/выбрасывания; это не атомарное применение экипировки. Телепортация к загруженной контрольной точке не создаёт полное сюжетное состояние. Отдача, скорость атак, видимость рук, создание врагов и работоспособность вырезанных предметов отложены.

## Установка, обновление и удаление

1. Закройте игру. Через Steam откройте установленные файлы игры, затем `Hellraiser/Binaries/Win64`.
2. Сделайте резервную копию имеющегося модифицированного `winmm.dll`. Из архива скопируйте **только `winmm.dll`** в эту папку, рядом с исполняемым файлом игры. Документацию и лицензии сохраните для справки.
3. Запустите игру обычным способом через Steam. Меню открывается и закрывается клавишей **Insert** или **F8**.

При обновлении закройте игру, сохраните копию прежней DLL и замените только `winmm.dll`. Сохраните `BananMenu.ini` (настройки) и `BananMenu.presets` (профили, избранное и наборы). В архиве этих файлов нет. После изменения материалов переоткройте штатный инвентарь, чтобы обновить отображение.

Для удаления закройте игру и удалите DLL мода либо восстановите прежнюю DLL из резервной копии. Настройки и наборы можно оставить для повторной установки; их удаление необязательно. Для отката обновления верните сохранённую DLL мода при закрытой игре.

## Сборка и упаковка

Нужны Windows x64, инструменты MSVC C++/MASM и CMake 3.25 или новее. Учётные данные, сохранения и установленная игра для сборки и офлайн-тестов не требуются. При первой конфигурации CMake загружает закреплённые архивы Dear ImGui и MinHook с проверкой хешей. Во время работы игры меню не делает веб-запросов.

```powershell
cmake -S . -B build -A x64
cmake --build build --config Release --parallel 1 -- /nodeReuse:false
ctest --test-dir build -C Release --output-on-failure
powershell -NoProfile -File scripts/package.ps1 -BuildDirectory build -OutputDirectory packages
```

Упаковщик включает обычную Release DLL, документацию и лицензии по фиксированному списку. Результат: `BananMenu-1.0.0-dev.2-win64.zip` и JSON с хешами, размерами, коммитом исходников и версией кандидата. Перезапись существующих файлов запрещена без явного `-Force`. Перед установкой сравните SHA-256 извлечённой DLL с манифестом. Сверяйтесь с примечаниями к устанавливаемому кандидату и [записанными результатами сканирования](docs/VERIFICATION.md). Результат относится только к точному указанному хешу DLL; другая сборка требует собственной проверки. Сканирование не гарантирует отсутствие любого вредоносного кода и не заменяет приёмку в игре.

Windows workflow собирает, тестирует и загружает артефакт разработки без публикации GitHub Release. При изменениях выполняйте операции с игрой в игровом потоке, передавайте отображению копии состояния и храните пользовательские RU/EN строки в `src/lang.cpp`. Запускайте указанные проверки и описывайте фактическую проверку в игре.
